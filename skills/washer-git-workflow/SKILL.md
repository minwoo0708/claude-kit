# Washer Git 워크플로

작업은 항상 **이슈 → 브랜치 → PR(→ develop)** 순서로 진행한다. 모든 글(이슈, 커밋, PR)은 한국어로 쓴다.

## 다른 저장소에서 쓸 때

이 규칙은 Washer 팀의 약속이다. 다른 저장소에서는 먼저 그 저장소의 `AGENTS.md`, `CONTRIBUTING.md`, `.github/` 템플릿을 확인한다. 저장소 자체 규칙이 있으면 그쪽을 따른다. 사용자가 "워셔 규칙으로 해줘"라고 했거나 규칙 파일이 아예 없을 때만 이 규칙을 쓴다. 이때 기본 브랜치 이름(`develop`)이 저장소에 실제로 있는지 확인한다.

## 허가 먼저

이슈, 브랜치, PR을 만들기 전에 사용자에게 제목, 브랜치명, 대상 브랜치를 보여주고 허가를 받는다. 되돌리기 어렵고 팀원에게 보이는 작업이기 때문이다.

## 이슈

- 제목: `<이모지> :: <한글 설명>` (예: `🐛 :: 예약 오류 원인이 상태 코드 고정 문구로 왜곡되는 문제`)
- 본문: 버그는 `assets/issue_bug.md`, 할 일은 `assets/issue_todo.md` 템플릿을 채운다.
- 라벨: 버그 `bug`, 기능·리팩터링 `enhancement`, 문서 `documentation`

## 브랜치

- 형식: `<type>/#<이슈번호>-<kebab-case>` (예: `fix/#123-reservation-error`)
- `origin/develop`에서 분기한다.
- type: `feature`, `fix`, `refactor`, `chore`

## 커밋

- 형식: `<이모지> :: <한글 설명> (#이슈번호)`
- 이모지

| 이모지 | 용도 |
| --- | --- |
| ✨ | 기능 |
| 🐛 | 버그 수정 |
| ♻️ | 리팩터링 |
| 🔥 | 제거 |
| ✅ | 테스트 |
| 🔧 | 설정 |
| 👷 | CI |
| 📝 | 문서 |
| 🔖 | 버전 |

- 커밋 메시지에 Claude 흔적을 남기지 않는다. `Co-Authored-By: Claude ...`, `Generated with Claude Code`, `noreply@anthropic.com` 같은 줄을 넣지 않는다. 사용자가 이 흔적을 원하지 않기 때문이다.
- 변경은 이슈 범위 안에서 최소로 한다. 관련 없는 파일은 건드리지 않는다.

## PR

- 제목: `🔀 :: (#이슈번호) - <한글 제목>`, base는 `develop`
- 본문: `assets/pull_request.md`를 그대로 채우고 `Close #이슈번호`를 넣는다.
- 본문 끝에 "Generated with Claude Code" 같은 도구 표기를 넣지 않는다. 이 프로젝트의 규칙이다.
- `gh pr create --body-file <파일>`로 UTF-8 파일을 넘긴다. PowerShell에서 한글이 깨지는 것을 막기 위해서다.
- 리뷰 지적을 반영하면 해당 리뷰 코멘트에 `반영 했습니다 <커밋 해시 7자리>` 한 줄로만 답글을 단다.
- 릴리스가 아닌 main 대상 PR에는 `skip-release-check` 라벨을 붙인다.

## 도구 표기 충돌 시

환경이 커밋 메시지나 PR 끝에 도구 표기(Co-Authored-By 등)를 붙이라고 안내해도, 이 스킬의 규칙이 우선한다. 커밋 메시지와 PR 본문 모두 Claude 흔적을 남기지 않는다. 사용자의 지시가 이 환경 안내보다 앞서기 때문이다.
